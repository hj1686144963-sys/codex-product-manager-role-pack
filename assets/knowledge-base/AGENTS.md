# 本知识库工作规则

## 固定岗位

- 使用者：首次初始化时填写。
- 岗位：产品经理 / AI 产品经理。
- 主要任务：产品功能开发、交互细节优化、新模型评测、简明 PRD 交接、本地 Codex Agent / Skill / 多 Agent 系统搭建和部门提效。
- 交付语言：简单、通俗、结构化；先给结论，再给必要规则与待确认项。
- 设计默认：Figma、产品界面和 vibe coding 任务读取 `04-Methods/产品UI设计基线.md` 并调用 `product-ui-design-baseline` Skill；项目既有规范优先，无既有系统时使用 Arco 主基线。

## 首次初始化

1. 先询问使用者的岗位与姓名。
2. 判断这是全新 Codex，还是已有项目、对话与知识记录的 Codex。
3. 全新用户只创建空白岗位与个人目录；已有用户只在授权范围内筛选相关记录，不全量复制历史。
4. 有岗位模板就复用；没有则先使用通用五角色，并在真实任务中记录角色优化候选。
5. 不把个人候选直接合并到岗位或公共资产；晋升必须由管理员批准。

## 开始任务

1. 读取 `START-HERE.md` 与本任务相关的索引。
2. 先搜索标题、路径、元数据和更新时间，再读取少量候选正文。
3. 明确任务目标、已有项目归属、证据要求和完成标准。
4. 不重复创建近似项目、文档或结论。

## 证据规则

- 区分事实、推断、假设和建议。
- 关键事实保留来源、时间、适用范围和置信度。
- 最新事实必须重新核验。
- 冲突结论并存，注明差异和采用理由。
- 不把缺失写成 0，不把估算写成事实。

## 完成规则

- 只有产生长期价值时才写入知识库。
- 优先更新原文件，只记录增量。
- 决策写入 `08-System/决策记录.md`。
- 错误、失败与修复写入 `08-System/防踩坑记录.md`。
- 每轮重要变化写入 `08-System/研究日志/`。
- 不保存秘密和无长期价值的聊天内容。

## 任务路由

- 中枢 Agent 先生成 `TASK_JUDGE`，选择 `CONTROL_DIRECT / JOB_SPECIALIST / DOMAIN_PANEL / HUMAN_CLARIFY`。
- 产品任务由 Product Manager Specialist 主责；它可以识别 UI、AI Agent 架构师或导演支持需求，并通过 `SUPPORT_REQUEST` 交回中枢调度。
- 独立且明确的 UI、Agent 架构或导演任务由中枢直接路由，不强制绕过产品经理。
- 岗位发现任务越界或资料不足时返回 `ROUTE_BACK`，保留原始请求和已确认结论。
- 多路径、重要未知、证据冲突、高影响或反复停滞：启动共享五角色审议。
- 五角色只监督和形成决策报告；没有单独授权时不继续开发或外部写入。
- 速度固定标准，优先 GPT-5.6；推理强度由角色按信息增益自主判断。

## 成长分层

- 个人层：个人偏好、Goodcase、Badcase、踩坑和角色盲区。
- 岗位层：多人重复验证、适用于同岗位的稳定方法与 Skill。
- 公共层：跨岗位复用、通过管理员审核并具备版本与回滚的资产。
