# 产品主岗位与支持岗位路由

本包仍以产品经理为主岗位。岗位协作采用两层路由，避免产品经理吸收所有专业工作，也避免支持岗位脱离产品目标自行扩张范围。

## 第一层：中枢任务判断

中枢 Agent 对每条请求静默生成 `TASK_JUDGE`，保留用户原始目标并选择：

- `CONTROL_DIRECT`：状态、范围确认、路由说明、结果整合或没有岗位覆盖的任务。
- `JOB_SPECIALIST`：岗位明确，由对应岗位执行；产品任务默认交给 Product Manager Specialist。
- `DOMAIN_PANEL`：任务归属不清、多路径、高影响或证据冲突时，先运行共享五角色审议。
- `HUMAN_CLARIFY`：缺少只有用户能决定的业务选择、权限或不可逆授权。

## 第二层：产品岗位申请支持

产品经理执行过程中发现专业缺口时，向中枢 Agent 返回：

```text
SUPPORT_REQUEST
role: UI Designer / AI Agent Architect / Director
reason: 为什么产品岗位不能独立完成
scope: 支持岗位允许处理的边界
inputs: 已确认的产品目标、资料和项目 SSOT
expected_output: 需要返回的专业交付物
acceptance: 可观察的验收标准
```

中枢 Agent 检查权限和范围后再调度支持岗位。支持岗位只返回本域结论或交付物；产品经理负责整合为产品结果，中枢 Agent 负责最终完成验证。

## 固定边界

- 产品经理可以识别需要哪个支持岗位，但不能覆盖该岗位的专业否决。
- 支持岗位不得改写产品目标、扩大权限或自行发布。
- 简单产品任务不强制调用支持岗位。
- 跨岗位协作不自动升级为五角色；只有多路径、高影响、证据冲突或用户明确要求时才审议。
- 个人偏好和单次经验不得直接成为公共路由规则。
