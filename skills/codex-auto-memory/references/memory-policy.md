# 记忆治理与防踩坑策略

## 目录

- 记忆层级
- 写入阈值
- 冲突与过期
- 去重
- 安全
- 推荐落点

## 记忆层级

按优先级使用：

1. 当前用户明确指令；
2. 当前项目文件、测试和日志；
3. 有来源和日期的知识库结论；
4. Codex 本地 Memories；
5. 未验证的历史摘要。

低优先级内容不得覆盖高优先级内容。

## 写入阈值

仅当信息预计会在未来任务中复用，或不记录会导致重复劳动、决策丢失、错误复发时写入。

建议写入：

- 用户明确确认的方案；
- 已执行并验证成功的操作方式；
- 可重复出现的失败及修复；
- 影响后续任务的路径、依赖、权限与状态；
- 能被来源、测试或实际运行证明的结论。

不建议写入：

- 尚未选择的备选方案；
- 模型的临时推测；
- 与任务无关的聊天；
- 可由源码或配置即时得出的低价值事实；
- 任何秘密或身份认证数据。

## 冲突与过期

- 为时效性结论记录 `updated`、适用地区、版本或有效期。
- 新证据与旧结论冲突时，不直接删除旧结论；标为已替代并说明原因。
- 产品能力、价格、政策和法规默认需要重新核验。
- 用户当前明确修正历史信息时，以当前修正为准并记录变化。

## 去重

依次比较：

1. 稳定 ID、源链接或项目标识；
2. 文件规范化路径；
3. 标题与核心结论；
4. 内容指纹。

同一主题优先更新原文件；只有主题边界明显不同才创建新文件。

## 安全

不得存储：

- API Key、Token、密码、Cookie、私钥；
- 身份证件、私人联系方式和未授权个人信息；
- `.env`、认证缓存或密钥链内容；
- 用户明确要求不保留的内容。

检测到疑似秘密时，用 `[REDACTED]` 替代，并在结果中提醒用户。

## 推荐落点

- 原始材料：`00-Inbox/`
- 来源：`10-Sources/`
- 稳定原子概念：`20-Concepts/`
- 可复用方法：`30-Methods/`
- 项目状态：`40-Projects/Project_XX_项目名/`
- 最终产出：`50-Outputs/`
- 复盘：`60-Reviews/`
- 全局规则与候选经验：根目录 `01_全局复利&踩坑日志.md`
- 工作区变更：`90-System/01_变更记录.md`
- 测试证据：`90-System/02_研究与测试证据索引.md`
- 详细踩坑证据：`90-System/03_详细踩坑证据索引.md`
- 运行审计：`90-System/运行记录/YYYY-MM-DD.jsonl`
