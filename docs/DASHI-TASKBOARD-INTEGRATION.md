# Dashi Taskboard 集成与防复发指南

## 发布边界

本仓库只发布自主编写的集成契约、目录初始化、检查清单和合成验收方法。固定上游 `chuspeeism/dashi-taskboard` 的 `0.2.0`／`5d85bd502cad96b41c0f1c437af1c1d3b77bd361` 未声明许可证，因此本公开包不包含作者 UI、上游源码、派生 bundle、真实任务数据库或私人日志。

## 真镜像的定义

```text
Dashi SQLite（唯一任务数据源）
        │
        ├── HTTP API ── 浏览器作者界面
        ├── HTTP API ── Codex 内嵌 Dashi 界面
        └── /api/events SSE ── 两端实时刷新
```

- 网页和 Codex 内嵌页面只是两个视图，不各自保存一份任务。
- 创建、更新、拖动、评论都必须写入同一 Dashi API。
- 实时刷新使用生产 `/api/events` SSE，并核对事件类型和同一记录 ID。
- 普通 CRUD/SSE 不调用 LLM，不使用定时 Codex Agent 对账，因此不会产生同步 Token。
- 不把 Codex 左侧原生项目／对话列表描述成 Dashi 的同源数据；官方接口没有提供完整双向事件与写入扩展点。

## 已知失败及禁止回退

1. `/health`、工具调用或网页 200 不证明 Codex 宿主内真实可见。
2. HTTP iframe 会受 Codex CSP 限制；不得把“内容被屏蔽”描述成加载成功。
3. 直接渲染时不得静默重画成简化 UI；必须锁定 Dashboard、议题看板、列表、甘特图、详情、筛选和项目导航。
4. 渲染成功不等于容器可用；复杂看板必须请求全屏，并提供内联回退入口。
5. 独立 profile/CDP 注入不是当前官方 Codex 的原生页面，不得称作“新版 Codex”。
6. 不得轮询不存在的 `/api/revisions`，也不得用固定 Agent 定时任务假装镜像。
7. 插件可编辑源、安装缓存、当前任务 transport 和 Dashi runtime 是四层不同状态，必须分别核验。
8. Windows PowerShell 5.1 脚本避免嵌入非 ASCII 绝对路径；需要中文时使用 UTF-8 BOM 或运行时动态解析路径。

## 新电脑首次安装顺序

1. 记录操作系统、Codex 版本和目标 Vault；未知项不得猜测。
2. 从合法上游固定 commit 获取 Dashi；保存来源、版本、commit 和校验值。
3. 运行目录、数据目录、配置目录、日志目录和备份目录必须分离并动态创建。
4. 服务只监听 `127.0.0.1`；不得开放防火墙或使用 `0.0.0.0`。
5. 插件 `.mcp.json` 由目标机模板生成，不提交用户目录或固定 Node 路径。
6. 在临时端口和临时 SQLite 上完成隔离安装测试，再切换正式数据。
7. 新建 Codex 任务，核对插件源版本、安装缓存版本、工具清单和新 transport。
8. 分别验收 Dashboard、议题看板、列表和甘特图。
9. 创建合成任务，移动状态，刷新页面并确认记录仍存在。
10. 在另一视图写入评论，确认 SSE 收到相同 comment ID。
11. 重启服务，确认项目数、任务数和 SQLite `integrity_check`。
12. 只有上述步骤均通过，才把版本标记为可用；用户可见宿主验收必须单独记录。

## 升级与回滚

- 升级前对 SQLite 做一致性备份，不能只复制主文件而遗漏 WAL。
- 新 runtime 安装到版本目录，数据放在外置固定目录；验证成功后原子切换 active version。
- 失败时只停止本次受管进程，恢复旧 runtime、配置和数据库备份。
- 不修改 Codex MSIX、`app.asar`、普通 profile、浏览器认证或系统安全策略。

## 验收证据

至少记录：安装版本、上游 commit、插件版本、服务绑定地址、四视图截图、CRUD 结果、SSE 事件与记录 ID、重启前后数据计数、备份路径、回滚结果及未验证事项。
