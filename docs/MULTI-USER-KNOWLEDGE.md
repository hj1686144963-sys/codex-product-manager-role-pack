# 多岗位、多人员知识共享方式

## 先纠正一句容易误解的话

新增岗位时**需要增加一个岗位共享空间**，例如 `roles/director/`；但不需要给每位导演复制一整套公司知识库。新增人员时只增加他的身份、权限和个人状态空间，然后让他读取同一份导演岗位知识。

## 同岗位的人怎样一起共享

以导演岗位为例：

1. 公司只维护一份公司公共规则。
2. 所有导演共同读取一份 `roles/director/approved/`。
3. 同一个项目的人共同读取一份 `projects/<项目>/`。
4. 每个人另外保留自己的私人 Vault，不向其他人公开。
5. 个人使用中产生的新方法先进入 `roles/director/candidates/`。
6. 每周由负责人审查；批准后才合并到 `approved/`，所有导演下次同步即可共同使用。

因此，新导演加入时不是复制知识库，而是：安装导演岗位包 → 获得岗位空间访问权 → 创建自己的私人状态包 → 选择当前项目。新岗位加入时才新建一份岗位目录和岗位评测集。

## 每次任务读取哪几层

```text
公司公共规则
+ 当前岗位 approved
+ 当前项目资料
+ 当前人员私人偏好
```

跨岗位任务才额外读取其他岗位的已批准内容。本期只实现目录和路由约定，不安装全公司权限过滤或向量检索。

## 知识对象字段的简单理解

这些字段不是让同事手填一大张表，而是让系统知道“这份资料属于谁、能给谁用、是不是已批准”。模板示例：

```yaml
source_id: pm-prd-rule-001
role: product-manager
project: shared
owner_scope: role
visibility: role
status: approved
source: confirmed-team-practice
version: 1.0.0
updated: 2026-08-07
```

`content_hash` 由脚本自动计算，用来判断内容有没有变化和是否重复，不要求使用者手工维护。
